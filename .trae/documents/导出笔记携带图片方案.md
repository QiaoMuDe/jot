# 导出笔记携带图片方案

## 摘要

修改单条笔记导出功能 `ExportNoteAsMarkdown`：导出 `.md` 文件时，把笔记内容中引用的 `/images/` 图片文件复制到与 `.md` 同级的 `文件名.md.assets/` 目录，并把内容中的图片引用改写为相对路径。为后续"导出笔记一并导入"功能打下基础（保留原始图片文件名 + 目录命名约定）。

## 现状分析

- 单条导出入口：`ExportNoteAsMarkdown`（[app.go](file:///d:/峡谷/Dev/本地项目/jot/app.go#L3269-L3301)），当前只把 `note.Content` 原样写入用户选择的文件路径，不处理图片。
- 图片存储：粘贴图片经 `SaveImage` 存入 `~/.jot/images/`，文件名为 `uuid_原名.ext`（[app.go](file:///d:/峡谷/Dev/本地项目/jot/app.go#L287-L335)）。
- 内容中的图片引用格式：`![名](/images/uuid_原名.ext)`（[main.js](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L215)）。
- 图片 URL 服务：`/images/` 前缀由 AssetServer Handler 映射到图片目录（[main.go](file:///d:/峡谷/Dev/本地项目/jot/main.go#L79-L85)）。
- 文件名清洗：`sanitizeFilename` 已存在（[app.go](file:///d:/峡谷/Dev/本地项目/jot/app.go#L3378)），导出文件名 = `sanitizeFilename(note.Title) + note.FileExt`。
- 前端入口：`exportNote` 只调用 `ExportNoteAsMarkdown(id)`（[main.js](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L1249-L1259)），函数签名不变则前端与 Wails bind 均无需改动。

## 改动方案

仅修改 [app.go](file:///d:/峡谷/Dev/本地项目/jot/app.go) 中的 `ExportNoteAsMarkdown` 函数体（约 L3269-L3301），不改动前端与函数签名。

### 导出目录结构

```
D:\导出目录\
├── 我的笔记.md
└── 我的笔记.md.assets\        ← filePath + ".assets"
    └── uuid_原名.png          ← 保留原始文件名不变
```

目录名由保存对话框返回的 `filePath` 直接推导：`assetsDir := filePath + ".assets"`，无歧义、无需二次计算，未来导入时用 `mdPath + ".assets"` 即可零成本还原。

### 实现步骤（在 `ExportNoteAsMarkdown` 内）

1. **获取图片目录**：调用 `config.SubDir(config.DirImages)`（现有 `SaveImage` 同款写法）。获取失败则按原逻辑直接导出纯文本，不报错。
2. **提取图片引用并改写**：用正则 `!\[[^\]]*\]\(/images/([^)]+)\)` 匹配图片语法，对每个匹配：
   - 校验捕获组 `filename` 不含 `/` 或 `\`（防路径穿越），不含则跳过不改写。
   - 用 `seen` map 去重，仅首次遇到时复制：`os.ReadFile(filepath.Join(imageDir, filename))` → `os.MkdirAll(assetsDir, 0755)` → `os.WriteFile(filepath.Join(assetsDir, filename), data, 0644)`。
   - 源文件缺失时跳过该图（保留原 `/images/` 路径），记 Warn 日志并累计失败数。
   - 改写：图片语法内 `/images/<filename>` → `文件名.md.assets/<filename>`（相对 `.md` 所在目录，`.assets` 与 `.md` 同级），用 `ReplaceAllStringFunc` 只替换匹配到的图片语法，避免误伤正文中手写的 `/images/` 文本。
3. **写入 .md**：目录创建成功后写改写后的内容。若某图片复制失败，该图路径保留原样并在返回值中提示"有 N 张图片未能导出"。
4. **无图片笔记**：正则无匹配时跳过全部逻辑，行为与现状完全一致（不创建目录）。

### 返回值

- 成功：`导出成功：<path>`（含图片时追加 `（含 N 张图片）`）。
- 部分失败：`导出成功：<path>（含 N 张图片，M 张未能导出）`。
- 目录创建失败：返回错误中止（沿用现有 `写入文件失败` 的错误返回模式）。

## 假设与决策

- 目录命名采用 `filePath + ".assets"`（即 `我的笔记.md.assets`），推导零成本、导入还原零歧义；该命名是 Markdown 编辑器（Typora 等）的通用约定，外部工具可直接显示图片。
- 保留图片原始文件名 `uuid_原名.ext` 不变 —— 这是"一同导入"还原的关键：导入时无需重命名/映射，直接写回 `~/.jot/images/` 即可，内容路径 `文件名.md.assets/xxx` 改回 `/images/xxx` 后即可正常显示。
- 路径改写只作用于图片语法内，不全局替换，避免误伤正文。
- 图片复制失败不中止整个导出，仅跳过该图并提示，保证导出过程健壮。

## 验证步骤

1. 构建运行应用（`wails dev` 或按项目现有方式）。
2. 打开一条含粘贴图片的 `.md` 笔记，右键 → 导出笔记，保存到目标路径。
   - 断言：目标路径出现 `xxx.md` 和 `xxx.md.assets/`，图片文件在目录内且文件名与 `~/.jot/images/` 一致。
   - 断言：`xxx.md` 内图片引用为 `![](xxx.md.assets/uuid_原名.ext)`，用 Typora / VS Code / 浏览器打开可正常显示图片。
3. 导出不含图片的 `.md` 笔记：不产生 `.assets` 目录，行为与原来一致。
4. 手动删除 `~/.jot/images/` 中某张被引用图片后再导出：导出成功但提示图片未能导出的数量。
5. 导出 `.txt` 等其他格式笔记：不受影响，按原逻辑导出。
