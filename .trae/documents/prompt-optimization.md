# 系统提示词精简优化方案

## 概述

全面审查 AI 助手模块的系统提示词，在保留功能的前提下精简冗余内容，减少 token 消耗。

## 当前提示词结构（按注入顺序）

| 序号 | 模块                                        | 位置                | 估计 token  |
| -- | ----------------------------------------- | ----------------- | --------- |
| 1  | baseIdentity                              | app.go:50         | \~30      |
| 2  | baseNormsBoundaries（含 reasoningFramework） | app.go:80-90      | \~400     |
| 3  | 笔记引用/追问/文件                                | app.go:2058-2090  | 动态        |
| 4  | 技能提示词                                     | app.go:2092-2119  | 动态        |
| 5  | 工具使用规范-本地知识优先                             | app.go:2121-2128  | \~200     |
| 6  | 工具使用规范-ask\_user                          | app.go:2130-2135  | \~200     |
| 7  | 工具使用规范-写操作确认                              | app.go:2137-2141  | \~150     |
| 8  | 工具使用规范-时间工具                               | app.go:2143-2148  | \~150     |
| 9  | genPlanHint（动态注入）                         | agent.go:983-1045 | \~200-400 |

**静态部分合计约 1330 token，动态部分另计。**

## 冗余分析

### 冗余1：ask\_user 提示词重复 3 次

* baseNormsBoundaries 第2条："需求模糊或信息不足时，先通过 ask\_user 工具向用户澄清"

* 工具使用规范-ask\_user（4条详细规则）

* genPlanHint 中的 ask\_user 提示："如果你需要向用户澄清、确认或提问，必须调用 ask\_user 工具"

**保留策略**：仅保留工具使用规范-ask\_user（最完整），其余两处删除。

### 冗余2：reasoningFramework 过于冗长

* 当前 4 步推理框架约 300 token

* 大部分内容是常识性指导，模型本身具备此能力

**精简策略**：压缩为 2-3 句核心指令。

### 冗余3：工具使用规范-本地知识优先 与 baseNormsBoundaries 重复

* baseNormsBoundaries 已有"工具能力"描述

* 本地知识优先规范的第1、2、4条与 baseNormsBoundaries 功能重叠

**精简策略**：合并去重，保留核心规则。

### 冗余4：genPlanHint 中的催促提醒过长

* "【强制要求】上一轮你执行了工具但未调用 update\_plan" 段落过长

* 多个"严禁"、"绝对不要"叠加使用

**精简策略**：精简为 1-2 句核心约束。

### 冗余5：工具使用规范-时间工具 过于详细

* 4条规则中，第2条列举了大量场景，模型本身能判断

**精简策略**：压缩为 2 条核心规则。

## 优化方案

### 修改1：精简 reasoningFramework（app.go:53-78）

**修改前**（\~300 token）：

```
## 内部推理框架
请遵循以下内部推理步骤...
第一步：问题分析...
第二步：信息整合...
第三步：结构规划...
第四步：回答生成...
```

**修改后**（\~50 token）：

```
回答前先分析问题类型（事实型/分析型/创作型），整合 system message 中的参考内容（优先级：本地笔记 > 联网搜索 > 自身知识），按结构化方式组织回答，引用时标注来源。
```

### 修改2：删除 baseNormsBoundaries 中的 ask\_user 冗余（app.go:82）

**删除**：

```
"\n2. 澄清优先：需求模糊或信息不足时，先通过 ask_user 工具向用户澄清关键细节再回答，不要擅自猜测"
```

**替换为**：

```
"\n2. 深度适配：简单问题直接回答，复杂问题先分析再给出结论"
```

（原第3条上移）

### 修改3：删除 baseNormsBoundaries 中的工具能力冗余（app.go:85-86）

**删除**：

```
"\n\n工具能力：" +
"\n你拥有调用工具的能力：可检索/管理用户的本地笔记、待办、标签，可读取网页内容，可在信息不足时向用户澄清。需要用户数据或执行操作时，优先调用对应工具获取或执行，而不是仅凭模型自身知识回答。"
```

工具使用规范已有更详细的说明，此处冗余。

### 修改4：精简工具使用规范-本地知识优先（app.go:2121-2128）

**修改前**（5条规则，\~200 token）：

```
1. 优先检索本地知识...
2. 本地知识不足再联网...
3. 明确联网需求直接联网...
4. 信息整合优先级...
5. 失败降级...
```

**修改后**（3条，\~100 token）：

```
1. 优先检索本地笔记（recall_notes），不足时再联网搜索；用户明确要求联网或问题需实时信息时直接联网。
2. 信息优先级：本地笔记 > 联网搜索 > 自身知识；引用时标注来源，矛盾时如实说明。
3. recall_notes 失败时降级为联网搜索；已返回充足信息时不再重复联网。
```

### 修改5：精简工具使用规范-ask\_user（app.go:2130-2135）

**修改前**（4条，\~200 token）：

```
1. 以下场景必须调用 ask_user...
2. 一次只问一个问题...
3. 调用 ask_user 工具前...
4. 用户回答后...
```

**修改后**（3条，\~120 token）：

```
1. 用户请求模糊、需要选择或确认时，必须调用 ask_user 澄清，严禁猜测后直接执行。一次只问一个问题，提供 2-6 个选项。
2. 调用前先在正文中写出问题（正文即问句），调用后等待用户回答。
3. 收到回答后继续完成原始请求，不要重复提问。
```

### 修改6：精简工具使用规范-写操作确认（app.go:2137-2141）

**修改前**（3条，\~150 token）：

```
1. manage_note 的 update/edit/pin/move/add_tag/remove_tag 全部属于写操作...
2. 只有用户明确同意后...
3. 用户明确拒绝或撤回指令时...
```

**修改后**（2条，\~80 token）：

```
1. manage_note 的写操作（update/edit/pin/move/add_tag/remove_tag）执行前必须通过 ask_user 确认，用户同意后携带 confirm=true 执行。create 无需确认。
2. 用户拒绝或撤回时不执行。
```

### 修改7：精简工具使用规范-时间工具（app.go:2143-2148）

**修改前**（4条，\~150 token）：

```
1. 你无法获知真实的当前日期和时间...
2. 以下场景必须先调用 get_current_time...
3. 调用时机...
4. 如果 get_current_time 调用失败...
```

**修改后**（2条，\~60 token）：

```
1. 涉及当前时间/日期的问题，必须先调用 get_current_time 获取真实时间，严禁凭模型知识猜测。
2. 调用失败时如实告知用户，不要替代。
```

### 修改8：精简 genPlanHint 催促提醒（agent.go:1024-1028）

**修改前**：

```
"\n【强制要求】上一轮你执行了工具但未调用 update_plan 更新计划进度。" +
"严禁跳过此步骤。你必须在下一步操作之前先调用 update_plan，将对应步骤标记为 done/skipped/in_progress。" +
"绝对不要在未调用 update_plan 的情况下输出最终回答或执行新的工具调用。"
```

**修改后**：

```
"\n【强制要求】上一轮你执行了工具但未调用 update_plan。请立即调用 update_plan 更新进度，再继续执行。"
```

### 修改9：精简 genPlanHint 未完成步骤提醒（agent.go:1031-1037）

**修改前**：

```
"\n【强制要求】当前计划还有 %d 个步骤未完成。"+
"每执行完一个工具后，必须立即调用 update_plan 将对应步骤标记为 done。"+
"不要在仍有未完成步骤时直接输出最终回答。"+
"【系统验证】系统会在你尝试输出最终回答时自动检测计划完成状态，"+
"如果计划未完成，你的回答将被拒绝，系统会强制你继续执行计划。"
```

**修改后**：

```
"\n【强制要求】当前计划还有 %d 个步骤未完成。执行完工具后请调用 update_plan 更新进度。"+
"系统会在你输出最终回答时自动检测计划完成状态，未完成的回答将被拒绝。"
```

### 修改10：删除 genPlanHint 中的 ask\_user 重复提示（agent.go:1041-1043）

**删除**：

```
"\n【重要】如果你需要向用户澄清、确认或提问，必须调用 ask_user 工具向用户发起提问" +
"并等待其回答（这不属于计划步骤，也不算输出最终回答）；" +
"严禁直接把问题写在正文里当作最终回答输出。"
```

app.go 中的工具使用规范-ask\_user 已覆盖此规则。
