# 修复删除预设按钮"点击没动静"问题

## 根因分析

### 问题 1：确认弹窗遮罩点击无声关闭

[showConfirmDialog](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L1100-L1102) 中绑定了遮罩点击关闭：

```javascript
els.confirmDialog.onclick = (e) => {
    if (e.target === els.confirmDialog) cleanup(false);
};
```

当用户点击确认弹窗**之外的遮罩区域**时，`cleanup(false)` 执行，弹窗无声消失，不删也不报错。用户看到的就是"没动静"，然后第二次尝试才删掉。

### 问题 2：删除后 `loadProfiles` 递归链导致卡顿

[deleteProfile](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L3045) 在删除后调用 `await loadProfiles()`。而 [loadProfiles](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L2846-L2849) 中如果发现**无激活预设**（删的就是当前激活的那个），会调用 `switchProfile(target.id, true)`。[switchProfile](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L2901) 末尾又调 `loadProfiles()`。这一串涉及 3-4 次 Wails 后端调用：`GetProfiles → SwitchProfile → GetAIConfig → GetProfiles`。每次调用都有跨语言桥接延迟，在删除动画之后又附加了不必要的延迟。

## 修改方案

### 修改 1：遮罩点击不关闭确认弹窗

**文件**：[main.js](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L1100-L1102)

移除 `showConfirmDialog` 中的遮罩点击关闭逻辑。用户只能通过点击"确定"或"取消"按钮来关闭弹窗，避免意外点击遮罩导致弹窗无声消失。

同时检查 [showSaveConfirmDialog](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L1185-L1187) 和笔记本删除弹窗（[main.js#L7014-L7016](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L7014-L7016)），统一处理。

```diff
- els.confirmDialog.onclick = (e) => {
-     if (e.target === els.confirmDialog) cleanup(false);
- };
+ // 不绑定遮罩点击，避免意外关闭
```

### 修改 2：删除后跳过 `loadProfiles` 递归

**文件**：[main.js](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L3038-L3050)

在 `deleteProfile` 中，将 `await loadProfiles()` 替换为轻量的本地更新：

1. 从下拉列表中移除对应选项
2. 如果被删的是激活预设，则从剩余预设中找出默认或第一个，调用一次 `switchProfile`（不走 `loadProfiles` 递归）
3. 更新下拉标签

```javascript
async function deleteProfile(id, name, rowEl) {
    const confirmed = await showConfirmDialog(`确定删除配置「${name}」吗？`);
    if (!confirmed) return;
    // 播放删除动画
    if (rowEl) {
        rowEl.classList.remove('preset-row-enter');
        rowEl.classList.add('preset-delete-out');
        await new Promise(resolve => {
            rowEl.addEventListener('animationend', resolve, { once: true });
        });
    }
    try {
        await window.go.main.App.DeleteProfile(id);
        nm.show('配置已删除', 'success');

        // 从下拉列表中移除对应选项
        const dropdown = document.getElementById('presetDropdown');
        if (dropdown) {
            const item = dropdown.querySelector(`[data-profile-id="${id}"]`);
            if (item) item.remove();
        }

        // 重新获取最新列表，判断是否还需处理激活状态
        const remaining = await window.go.main.App.GetProfiles();
        const hasActive = remaining.some(p => p.is_active);
        if (!hasActive && remaining.length > 0) {
            // 被删的是激活预设，自动激活剩余中的默认或第一个
            const target = remaining.find(p => p.is_default) || remaining[0];
            await switchProfile(target.id, true);
        } else {
            // 单纯刷新下拉标签
            const label = document.getElementById('presetLabel');
            const activeProfile = remaining.find(p => p.is_active);
            if (label) label.textContent = activeProfile?.name || '选择预设';
        }

        // 移除 DOM 中的行
        if (rowEl && rowEl.parentNode) {
            rowEl.remove();
        }
    } catch (e) {
        nm.show('删除失败: ' + e, 'error');
    }
}
```

关键变化：
- `GetProfiles()` 改为两次：删除前后各一次（当前基操）
- 不自递归：直接判断 `hasActive` 后手动调 `switchProfile`（一次调用，不自递归）
- 没 `loadProfiles` 阻拦，动画 → 删除 → 更新一气呵成
