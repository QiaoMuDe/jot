# 批量管理入口按钮状态同步

## 摘要

修复笔记首页批量管理模式的状态同步问题：进入批量管理模式后，「更多」菜单和启动器中的「批量管理」项应变为「退出批量管理」，退出后恢复为「批量管理」。参照「展开笔记本侧边栏」按钮的既有实现模式（`updateSidebarMenuItem()` + 启动器 `openLauncher()` 动态更新）实现。

## 现状分析

批量模式状态由 `state.batchMode` 控制（[main.js L409](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L409)），所有进入/退出路径最终都调用 `toggleBatchMode()`：

- 浮动按钮 `#fabBatch` 点击（[main.js L6197-6200](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L6197-L6200)）
- 更多菜单 `data-action="batch-mode"` 项（[main.js L6258-6260](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L6258-L6260)）
- 启动器 `case 'batch-mode'`（[launcher.js L209-212](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/js/launcher.js#L209-L212)）
- 批量栏「取消」按钮（[main.js L6507](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L6507)）
- ESC 全局快捷键（[main.js L7007](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L7007)）
- 切换笔记本时（[main.js L7605](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L7605)）
- `switchView()` 离开 grid 视图时强制退出（[main.js L732](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L732)）

**现状问题**：`toggleBatchMode()` 只切换 `state.batchMode` 并控制批量操作栏显示，从未同步以下入口文案：

1. 更多菜单项 `[data-action="batch-mode"]` 的文本固定在 HTML 中为「批量管理」（[index.html L73](file:///d:/峡谷/Dev/本地项目/jot/frontend/index.html#L73)），不随状态变化。
2. 启动器 `batch-mode` 项标签固定在静态数组 `launcherItems` 中为「批量管理」（[launcher.js L17-20](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/js/launcher.js#L17-L20)），仅 `openLauncher()` 打开时对 `sidebar-toggle` 项做动态更新，`batch-mode` 项未处理。

**参照实现（展开笔记本侧边栏）**：

- 更多菜单项：`updateSidebarMenuItem()` 依据侧栏折叠状态重建图标+文案（[main.js L7982-7990](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L7982-L7990)）
- 启动器项：`openLauncher()` 每次打开时按状态更新 `sidebar-toggle` 项的 label 与 dataset.label（[launcher.js L357-367](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/js/launcher.js#L357-L367)）
- 顶部按钮：`updateNotebookSidebarToggleBtn()` 更新按钮图标与 title（[main.js L7995-8003](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L7995-L8003)）

## 变更方案

### 1. `frontend/src/main.js` — 新增同步函数并接入 `toggleBatchMode()`

在 `updateSidebarMenuItem()`（约 L7990）附近新增：

```js
/**
 * 同步批量管理模式相关入口文案：更多菜单项 ↔ 浮动批量按钮
 * 参照 updateSidebarMenuItem 的写法，在“批量管理 / 退出批量管理”间切换
 */
function updateBatchModeControls() {
    // 更多菜单项（结构为 <svg>…</svg>批量管理，仅更新末尾文本节点，保留图标）
    const menuItem = els.moreMenu?.querySelector('[data-action="batch-mode"]');
    if (menuItem) {
        const textNode = Array.from(menuItem.childNodes).find(n => n.nodeType === Node.TEXT_NODE);
        if (textNode) {
            textNode.textContent = state.batchMode ? '退出批量管理' : '批量管理';
        }
    }
    // 浮动批量按钮提示（参照 updateNotebookSidebarToggleBtn 同步 title）
    if (els.fabBatch) {
        els.fabBatch.title = state.batchMode ? '退出批量管理' : '批量管理';
    }
}
```

在 `toggleBatchMode()`（L5563）中，`state.batchMode = !state.batchMode;` 之后立即调用 `updateBatchModeControls();`。由于所有进入/退出路径（含 `switchView` 强制退出、ESC、切笔记本、批量栏取消）都汇聚到 `toggleBatchMode()`，此一处接入即可覆盖全部场景。函数声明提升使前向调用安全。

### 2. `frontend/src/js/launcher.js` — `openLauncher()` 中同步 batch-mode 项

在 `openLauncher()` 内 `sidebar-toggle` 更新块（L357-367）之后追加：

```js
// 根据批量管理模式状态更新 batch-mode 项的标签
const batchModeEl = _launcherGrid?.querySelector('[data-action="batch-mode"]');
if (batchModeEl) {
    const batchLabel = window.state?.batchMode ? '退出批量管理' : '批量管理';
    batchModeEl.querySelector('.launcher-item-label').textContent = batchLabel;
    batchModeEl.dataset.label = batchLabel;
}
```

`window.state` 已由 main.js 暴露（[main.js L12034](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/main.js#L12034)）。更新 `dataset.label` 可保证拼音/文本过滤（`filterItems`）跟随新文案。图标保持不变（批量模式两个状态无方向性差异）。

### 不改动的部分

- `index.html`：菜单项默认文案保持「批量管理」（与 `state.batchMode=false` 初始态一致，无需改 HTML）。
- 启动器 `executeAction` 的 `batch-mode` 分支：`switchView('grid')` 在已处于 grid 时提前返回不会误触发退出，随后 `toggleBatchMode()` 正常切换，逻辑已正确。
- 不需要启动时初始化同步：`batchMode` 不持久化，初始恒为 `false`，默认文案即正确。

## 假设与决策

- 同步点放在 `toggleBatchMode()` 内（单一入口），而非在三个按钮的各自点击处理器里重复调用——与参照实现 `toggleSidebar()` 内统一调用 `updateSidebarMenuItem()`/`updateNotebookSidebarToggleBtn()` 的模式一致，且能覆盖 ESC/切视图/切笔记本等间接退出路径。
- **浮动按钮 `#fabBatch` 的 title 也一并同步**（进入批量模式后其 tooltip 同样过时），此为参照 `updateNotebookSidebarToggleBtn` 的对齐项；如不需要可删除该分支。
- 更多菜单项采用「更新末尾文本节点」而非重建 innerHTML：图标不变，避免硬编码 SVG 字符串重复；更新菜单文本的效果与参照一致。
- 启动器项沿用参照做法在 `openLauncher()` 打开时按当前状态刷新，无需在 `toggleBatchMode()` 中操作启动器 DOM（启动器为全屏浮层，执行动作前已先关闭）。
