# 修复新增预设后删除按钮无响应

## 根因

保存预设后 `closePresetModal()` 调用，预设弹窗遮罩进入 200ms 淡出过渡（`opacity: 1→0`, `visibility: visible→hidden`）。期间遮罩：
- 依然 `z-index: 10000`、`position: fixed; inset: 0` 覆盖全屏
- **没有 `pointer-events: none`**，能吃所有点击
- 点击管理列表里的删除按钮，实际点在了半透明遮罩上 → 被吞掉，没反应

关闭再打开管理列表时，遮罩早已 `visibility: hidden`，点击能穿透到删除按钮，所以正常。

## 修改方案

### 修改 1：遮罩默认态加 `pointer-events: none`

**文件**：[settings-panel.css](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/css/components/settings-panel.css#L1112-L1123)

```css
.preset-modal-overlay {
    position: fixed;
    inset: 0;
    z-index: 10000;
    opacity: 0;
    visibility: hidden;
    transition: opacity 200ms ease-out, visibility 200ms ease-out;
    pointer-events: none;   /* ← 新增：非可见态不拦截点击 */
}

.preset-modal-overlay.visible {
    opacity: 1;
    visibility: visible;
    pointer-events: auto;   /* ← 新增：可见态才接收点击 */
}
```

与确认弹窗 `.confirm-overlay` 的做法一致。

### 修改 2（可选）：优化保存时序

当前 `savePresetModal` 中：
```javascript
closePresetModal();          // 遮罩开始淡出
await loadProfiles();        // 异步加载，可能快于 200ms
// 插入新行...
```

可以改成等待遮罩淡出完成后再插行，减少时序依赖。不过加上 `pointer-events: none` 之后，即使遮罩还半透明也不影响点击，这个优化非必要。

### 不变的部分

- 删除动画 `preset-delete-out` 不变
- `createPresetRowElement` 不变
- `loadProfiles`、`switchProfile` 不变
- 后端无改动

## 验证步骤

1. 新增一个预设配置 → 保存
2. 点击新行的"删除"按钮 → 确认弹窗正常弹出（不再被遮罩吞掉）
3. 点击确定 → 删除动画播放 → `"配置已删除"` 通知
4. 确认预设弹窗打开/关闭时互动正常不受影响
