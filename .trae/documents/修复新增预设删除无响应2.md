# 修复新增预设后删除按钮无响应（第二次）

## 根因

上次新增 `pointer-events: none` 解决了"点击被遮罩吞掉"的问题，但出现了新问题：

点击删除按钮时，`showConfirmDialog` 显示的确认弹窗**被预设弹窗遮罩挡在后面**（z-index 层级问题）：

```
预设弹窗遮罩  z-index: 10000   ← 正在淡出，仍是最顶层
确认弹窗遮罩  z-index: 1000    ← 被压在下面，用户看不见
```

用户看到的：点了删除键 → 啥也没发生（确认弹窗在遮罩后面） → 再点一次 → 实际点在了不可见的确认弹窗遮罩上 → `cleanup(false)` 无声关闭 → 用户觉得完全没反应。

## 修改

**文件**：[modals.css](file:///d:/峡谷/Dev/本地项目/jot/frontend/src/css/components/modals.css#L495)

确认弹窗的 `z-index` 从 `1000` 提升到 `100000`，确保始终在预设弹窗遮罩之上：

```css
.confirm-overlay {
    position: fixed;
    inset: 0;
    z-index: 100000;     /* 1000 → 100000，高于 preset-modal-overlay 的 10000 */
    /* ... 其余不变 ... */
}
```

## 不变的部分

- `pointer-events: none` 的 CSS 改动保留（预设弹窗遮罩）
- 删除动画、JS 逻辑、后端均无改动

## 验证

1. 新增预设 → 保存 → 立即点击删除按钮
2. 确认弹窗正常浮现（不再被遮罩挡住）
3. 点击确定 → 删除成功
4. 预设弹窗打开/关闭行为不受影响
