# 卡片召回 2-gram 加停用词过滤

## 概要

在现有 2-gram 分词基础上，增加停用词过滤，减少无意义碎片（如"有什"、"什么"、"么新"）产生的噪声匹配，提升召回精度。

## 当前状态分析

`tokenize2Gram()` 对中文生成所有连续 2-gram，不做任何过滤：

```
"Go 1.22 有什么新特性"
  → ["Go", "1", "22", "有什", "什么", "么新", "新特", "特性"]
  → "有什"、"什么"、"么新" 全是噪声，会匹配到无关笔记
```

`SearchFull()` 是 2N 个 `LIKE %keyword%` OR 条件 + `ORDER BY updated_at DESC`，无排序优化。

## 改动内容

### 1. 停用词表 — `internal/services/recall_service.go`

新增 `var stopWords` 包级变量，约 200 个高频无意义中文词（单字 + 双字），包括：

- **单字停用词**：的、了、是、在、有、我、他、她、它、们、这、那、什、么、怎、哪、里、为、因、所、以、但、如、果、虽、然、而、且、或、与、和、同、及、又、也、对、就、被、把、让、向、往、从、到、去、能、会、要、可、没、不、很、太、更、最、都、只、还、再、才、刚、已、正、将、就、该、应、需、必、须、够、出、入、上、下、大、小、多、少、来、做、用、问、说、看、想、知、道、给、跟、比、次、个、种、些、点、些、等、第、每、各、几、两、百、千、万、亿、些、点、些（约 120 个）

- **双字停用词停用词**：一个、这个、那个、什么、怎么、怎样、哪里、哪个、许多、一些、这些、那些、可以、因为、所以、但是、虽然、然而、而且、或者、如果、没有、不是、就是、只是、还是、可是、不过、关于、对于、为了、等等、比如、例如、以及、之后、之后、之前、当前、目前、现在、将来、然后、接着、此外、另外、同样、反之、总之、也就是、可以说（约 50 个）

### 2. 过滤逻辑 — `tokenize2Gram()`（原地修改）

- **中文 2-gram**：如果 gram 的**任意一个字符在停用词表中**，则跳过该 gram
  - 例："有什" → "有"和"什"都在停用词表 → 跳过
  - 例："新特" → "新"和"特"都不在停用词表 → 保留
  - 例："特性" → 保留

- **单中文 token**（第 52-58 行的兜底）：如果该单字在停用词表中，则跳过
  - 例："有"、"的" → 跳过
  - 例："Go"、"API" → 不受影响（非 CJK 走另一条路径）

- **英文/数字 token**：不做过滤（保留数字 `1`、`22` 等技术类关键词）

### 3. 词典文件清理

删除 `internal/services/dict.txt`（jiebago 遗留，5MB，不再需要）。

### 不做的改动

- 不改 `SearchFull()` 的排序（仍用 `ORDER BY updated_at DESC`）
- 不改 `CardRecallSearch()` 的调用方
- 不改任何前端代码
- 不加新依赖

## 预期效果

```
之前: "Go 1.22 有什么新特性"
  → ["Go", "1", "22", "有什", "什么", "么新", "新特", "特性"]
  → 8 个关键词中 3 个无效

之后: "Go 1.22 有什么新特性"
  → ["Go", "1", "22", "新特", "特性"]
  → 5 个关键词，全部有效

搜索条件从 16 个 LIKE OR 降为 10 个，减少 37% 的噪声匹配
```

## 验证步骤

1. `go build .` 编译通过
2. 启用卡片召回，发送包含高频停用词的问题（如"什么是 Go 的并发模型"）
3. 在调试日志 `%TEMP%\jot_jieba_debug.log` 或终端确认不报错
4. 对比启用前后召回卡片的相关性
