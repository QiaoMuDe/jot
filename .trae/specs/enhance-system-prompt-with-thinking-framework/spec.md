# 增强 System Prompt：思考框架 + 来源标注 Spec

## Why

当前 system prompt 只有基本的身份定义和输出规范（4 条规范 + 3 条约束），缺少对 AI **内部推理过程**的引导，也缺少对不同信息源（本地笔记/搜索结果/模型知识）的优先级区分。导致：
- AI 回答时不会主动区分信息可信度（自己的笔记 vs 网络搜索 vs 自身知识混为一谈）
- AI 不会根据问题类型（事实型/分析型/创作型）选择不同回答结构
- 注入的搜索结果和召回笔记没有来源标签，AI 不知道哪段信息是从哪里来的

## What Changes

1. **思考框架注入**：在 `baseNormsBoundaries` 中新增一段内部推理框架（4 步），引导 AI 在生成回答前先完成「问题分析→信息整合→结构规划→回答生成」的隐式推理

2. **来源标注增强**：在各个注入点的格式化文本中添加来源标签，让 AI 能明确区分信息来自哪里
   - 卡片召回结果标注为「来源：本地笔记」
   - 搜索结果标注为「来源：{Tavily/知乎搜索/知乎全网}」
   - 引用笔记标注为「来源：手动引用笔记」
   - 角色扮演笔记标注为「来源：角色设定笔记」
   - 上传文件标注为「来源：上传文件」

3. **System Prompt 变量重组**：将 `baseNormsBoundaries` 拆分为 `baseNormsBoundaries` + `reasoningFramework`，思考框架作为独立变量在拼接时引用

## Impact

- Affected specs: AI 对话能力
- Affected code:
  - `app.go` — 新增 `reasoningFramework` 常量，修改 `baseNormsBoundaries`
  - `internal/services/search_service.go` — 搜索结果 Format 文本加来源标签
  - `internal/services/recall_service.go` — 卡片召回 Format 文本加来源标签
  - `app.go` — 手动引用笔记、角色扮演笔记、上传文件注入处加来源标签
- 不涉及：前端、数据库、模型配置

## 详细设计

### 1. 思考框架文本

新增 `reasoningFramework` 包级常量：

```
## 内部推理框架

请遵循以下内部推理步骤来组织你的回答（这些步骤仅用于逻辑组织，不输出给用户）：

第一步：问题分析
- 判断问题类型：事实型（需要具体信息/数据）、分析型（需要推理/对比/解释）、创作型（需要生成/写作/翻译）
- 识别核心需求和可能的隐含子问题

第二步：信息整合
- 回顾 system message 中提供的所有参考内容，区分来源类型
- 信息优先级：本地笔记 > 联网搜索结果 > 模型自身知识
- 优先使用本地笔记中的信息回答（这是用户自己的知识库）
- 如果信息不足，判断是否需要追问

第三步：结构规划
- 事实型：先给出核心结论，再展开要点
- 分析型：先给出观点/判断，再分条论证
- 创作型：直接输出创作内容
- 确保逻辑顺序清晰，不重复

第四步：回答生成
- 按规划结构生成回答
- 引用本地笔记或搜索结果时，标注来源（如「你的笔记《XXX》中记录了……」或「根据搜索结果显示……」）
- 不同来源信息矛盾时，如实说明差异
- 回答完成后检查：是否覆盖了核心需求，是否有多余信息需要精简
```

### 2. 来源标签改造

**卡片召回**（`recall_service.go` `CardRecallSearch`）：

当前：
```
以下是用户笔记库中与问题相关的笔记，请参考这些笔记内容回答用户的问题：

--- 📄 《XXX》 ---
```

改为：
```
以下是用户笔记库中与问题相关的笔记（来源：本地笔记，优先级最高），请优先参考这些笔记内容回答用户的问题：

--- 📄 《XXX》 ---
```

**搜索结果**（`search_service.go` `SearchWeb`）：

当前各搜索源的格式化文本没有统一标识来源。

改为在每个搜索结果的 `FormattedText` 开头添加来源标签：

- Tavily → `「以下是通过 Tavily 搜索到的相关内容（来源：Tavily 联网搜索）：」`
- 知乎搜索 → `「以下是通过知乎搜索到的相关内容（来源：知乎站内搜索）：」`
- 知乎全网 → `「以下是通过知乎全网搜索到的相关内容（来源：知乎全网搜索）：」`

**引用笔记**（`app.go` 步骤 3）：

当前：
```
refCtx, err := a.noteService.BuildNoteRefContext(referencedNoteIDs)
...
messages = appendToSystemMessage(messages, refCtx.Context)
```

改为在注入前加标签：
```
"以下是用户手动引用的笔记内容（来源：手动引用笔记），请参考这些内容回答：\n\n" + refCtx.Context
```

**角色扮演笔记**（`app.go` 步骤 2）：

当前：
```
roleplayText := "以下是用户提供的人物设定笔记内容：\n\n" + refCtx.Context
```

改为：
```
roleplayText := "以下是用户提供的人物设定笔记内容（来源：角色设定笔记），你在角色扮演中应严格遵循这些设定：\n\n" + refCtx.Context
```

**上传文件**（`app.go` 步骤 5）：

当前：
```
b.WriteString("用户上传了以下文件内容，请基于这些内容回答用户的提问：\n")
```

改为：
```
b.WriteString("用户上传了以下文件内容（来源：上传文件），请基于这些文件内容回答用户的提问：\n")
```

## 不改变的

- 技能激活时的行为不变（有技能时身份层由技能 prompt 覆盖，但规范层包含的思考框架仍然保留）
- `CallAIStream` 和 `CallAIStreamRegenerate` 的流程结构不变
- 外部接口不变
