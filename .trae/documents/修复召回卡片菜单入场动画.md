# 修复召回卡片菜单入场动画

## 问题分析

### 根本原因

召回卡片菜单的打开逻辑存在时序问题：

```
当前流程:
  1. dropdown.classList.add('open')     ← 先打开菜单
  2. await loadRecallNotebookMenu()     ← 后构建子项 DOM
```

当第 2 步执行 `innerHTML = ''` + `appendChild` 创建子项时，容器已经带有 `.open` 类，所以新增的子项**直接处于最终态**（`opacity: 1; transform: translateX(0)`），CSS transition 永远不会触发。

### 参考菜单的对比

| 菜单 | 子项存在方式 | 打开时序 |
|------|-------------|---------|
| **联网搜索** | 静态 HTML（已在 DOM 中） | `.open` toggle 前已存在 |
| **更多技能** | 静态 HTML（已在 DOM 中） | `.open` add 前已存在 |
| **卡片召回（当前）** | 动态创建（`loadRecallNotebookMenu`） | `.open` 添加后创建 ❌ |

两个参考菜单的子项都是**静态 HTML**，在 `.open` 类切换时 DOM 已经存在，因此 CSS transition（`opacity 0.25s ease-out, transform 0.25s ease-out` + stagger delay）能正常从初始态过渡到最终态。

### 效果差异的现象

卡片召回菜单打开时：
- 容器本身有淡入+缩放动画（正确）
- 子项直接全部同时显现，没有逐项滑入的 stagger 效果

## 修改方案

### 文件：`frontend/src/js/ai-chat.js`

#### 改动点：调整打开时序

**修改位置**：~L903-L918（卡片召回 toggle 点击事件中文字/图标/箭头区域的逻辑）

**修改内容**：将原来的 `toggle('open')` → `loadRecallNotebookMenu()` 时序，改为：

```
打开菜单:
  1. await loadRecallNotebookMenu()     ← 先在隐藏状态下构建子项
  2. dropdown.classList.add('open')     ← 再添加 .open 触发动画
  3. dropdown.scrollTop = 0             ← 滚动条置顶

关闭菜单:
  4. dropdown.classList.remove('open')  ← 移除 .open
```

**关键点**：每次关闭后下次重新打开时，`loadRecallNotebookMenu()` 会先执行 `innerHTML = ''` 清空内容再重建，由于此时菜单没有 `.open` 类，子项的默认 CSS 是 `opacity: 0; transform: translateX(-8px)`。然后添加 `.open` 后 transition 会正确触发。

### 文件：`frontend/src/css/components/ai-chat.css`

**不需要修改**。之前添加的容器动画和 stagger 菜单项动画的 CSS 本身是正确的，只是因为 JS 时序问题未生效。

### 影响范围

- 仅修改 `ai-chat.js` 中卡片召回菜单的打开/关闭逻辑
- CSS 文件不需要任何改动
- 其他菜单（联网搜索、更多技能）不受影响

## 验证方法

1. 打开卡片召回菜单，观察子项是否逐个从左侧滑入（stagger 效果）
2. 关闭菜单后重新打开，效果应一致
3. 多次开关，每次都应看到完整的入场动画
